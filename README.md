# ExpressiveJS

ExpressiveJS is a modular backend spinner built on top of Node.js and Express.js, designed to speed up backend development through automated spin up project scaffolding, structured architecture, and CLI-driven setup. Similar to `express-generator`, but with my own structure!

It follows a modular MVC-inspired architecture, helping developers build scalable, maintainable, and well-organized backend applications.


## ✨ Key Features
1. ⚡ Rapid project scaffolding via CLI
2. 🧱 Modular architecture for clean separation of concerns
3. 🧭 MVC-inspired structure (Model–View–Controller)
4. 🔧 Built on top of Express.js ecosystem
5. 📁 Auto-generated project structure (folders, configs, boilerplate)
6. 🗄️ Optional database integration setup
7. 🧩 Extensible project generation system


## 📦 Installation
Unlike other frameworks that can be installed via NPM, PNPM, etc., you need to download the ZIP file or download the `framework` folder and the CLI file and place them in your project directory

## ⚙️ Getting Started
ExpressiveJS uses a CLI-based setup system to initialize projects.

1. Initialize a new project

```bash
node expressivecli initiate-setup
```

This command automatically generates:

1. Project folders
2. Base application files
3. env configuration
4. .gitignore
5. App.js
6. Core framework structure

## 🚫 Without database setup
If you want a lightweight project without database integration:

```bash
node expressivecli initiate-setup --no-db
```

2. Explore CLI options

```bash
node expressivecli --help
```

This will display all available commands and utilities for managing your project.

## 🧠 Project Philosophy
ExpressiveJS focuses on:

1. Convention over configuration
2. Scalable project structure
3. Developer productivity through automation
4. Clean separation of backend concerns

## 🧩 Architecture
ExpressiveJS follows a modular structure inspired by MVC principles:

1. Models – Data structure and database logic
2. Controllers – Business logic and request handling
3. Routes – API endpoint definitions
4. Middlewares - where middlewares files are found and can be use in your routes
5. Database - database configuration and migration files
6. Applications - server application files you can usee in your controllers or any part of the project
